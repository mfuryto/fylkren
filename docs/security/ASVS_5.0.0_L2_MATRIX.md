# ASVS 5.0.0 Level 2 traceability matrix

**This is Fylkren's only security-testing matrix.** It records requirement-level test status, completed evidence and remaining work. [SECURITY_VERIFICATION.md](SECURITY_VERIFICATION.md) is the separate finding log, not another matrix. Test-run records provide supporting execution evidence and do not determine status independently.

> Generated from the OWASP ASVS 5.0.0 flat JSON. Requirement text is CC BY-SA 4.0. Status and evidence are maintained in the Fylkren repository.

Applicability decisions and their reopen conditions are documented in
[ASVS applicability decisions](ASVS_APPLICABILITY.md).

Source revision: `v5.0.0`
Expected SHA-256: `8201b20eec2908c3380ac600c91c8ba746346fbb808859366abb232027532311`

Status values: `Not assessed`, `In progress`, `Passed`, `Not applicable`, `Finding`.

The matrix is the single security-testing work list. Functional E2E cases become security evidence only on the requirements whose assertions they actually exercise. Test links identify maintained implementations; run links identify execution results and their frozen targets. A passing suite does not pass every related requirement. Historical deployment evidence remains historical until rerun against the current candidate.

Work proceeds in chapter/requirement order: reconcile existing evidence, execute missing positive/negative/boundary cases, fix and retest findings, then update this row. Keep applicable incomplete requirements open. An external tester is not required for this workflow; external review is optional when explicitly requested.

No row remains Not assessed or In progress. Open findings and final release-candidate/deployment qualification remain release work; a fully assessed matrix is not a security approval.
