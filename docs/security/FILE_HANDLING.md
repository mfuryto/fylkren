# File handling boundary

This is the canonical inventory for files selected, uploaded, generated or downloaded by Fylkren. It documents the current implementation boundary and its limits. Operational document fields store links only; Fylkren has no general document-attachment store.

## File selection and upload inventory

| Feature | Server input | Permitted type and expected extension | Maximum | Unpacked maximum | Validation, storage and rejection |
| --- | --- | --- | ---: | ---: | --- |
| Profile image | Authenticated multipart field `image` at `PUT /api/profile/image` | PNG (`.png`, `image/png`), JPEG (`.jpg`/`.jpeg`, `image/jpeg`) or WebP (`.webp`, `image/webp`) | 2 MiB; at most 4096 pixels per dimension and 16,777,216 pixels | Not compressed | The API requires a non-empty file and exact agreement between filename extension, declared media type and the type decoded by SkiaSharp. It fully decodes and re-encodes the raster before storing it, removing metadata and trailing/polyglot content. Invalid, mismatched, truncated, active-text, excessive-dimension and oversized input returns a validation error and is not persisted. The client filename is not stored. Sanitized bytes and the fixed decoded media type are stored in PostgreSQL as person data. |
| Branding logo | Platform Manager multipart field `logo` at `PUT /api/platform/branding/logo` | PNG (`.png`, `image/png`), JPEG (`.jpg`/`.jpeg`, `image/jpeg`) or WebP (`.webp`, `image/webp`) | 2 MiB; at most 4096 pixels per dimension and 16,777,216 pixels | Not compressed | Uses the same full decode, dimension checks and re-encoding as profile images and never creates a client-named path. Rejected input leaves the current logo unchanged. Sanitized bytes and the fixed decoded type are stored in PostgreSQL. |
| Portable package validation | Authorized multipart field `package` at `POST /api/portability/sites/{siteId}/imports/validate` | Fylkren ZIP (`.zip`, `application/zip`) containing `manifest.json`, optional `README.txt`, declared `data/*.jsonl` (`application/x-ndjson`) and declared raster `attachments/*` | 16 MiB ZIP; 17 MiB request allowance for multipart overhead | 16 MiB aggregate declared entry length; 250 entries | One package is buffered/validated at a time. The endpoint requires `.zip` plus `application/zip`. The validator checks ZIP parsing, entry count and lengths before opening entries, unsafe/duplicate paths, manifest shape/version/site, dataset extension/media type, declared sizes and SHA-256, JSON object/record/reference bounds and required datasets. Every profile-image attachment must pass the same extension/media/decode checks as a direct upload. Invalid packages return `valid: false`, create only the rejection audit and never apply data. Entries are never extracted to a filesystem or served from the package. |
| Enterprise licence selection | Platform Manager browser file control; the file itself is not sent as multipart | JSON (`.json`, `application/json`) with string `payload` and `signature` | 32,000 bytes in the browser | Not compressed | The browser parses the selected file and sends only the two strings as JSON. The server verifies the signed licence, instance binding, validity and supported claims. Invalid content does not activate entitlements. |
| Export custody confirmation | Archive browser file control; the file itself is not sent to the server | Fylkren ZIP (`.zip`, `application/zip`) matching a recorded export receipt | 16 MiB and exactly the receipt byte count | Not opened or unpacked | The browser calculates SHA-256 and sends only the digest, receipt version and reason. A size/digest mismatch is rejected before the acknowledgement request. This confirms custody; it does not validate or import the package. |

Browser `accept` filters guide file selection but are not security controls. Server-side rules above are authoritative. ASVS 5.2.2 verifies extension, declared-type and decoded-content boundaries; ASVS 5.2.3 verifies archive entry and expansion limits before content is opened.

## Generated and stored downloads

| Output | Filename and media type | Access and safe handling |
| --- | --- | --- |
| Profile image | Fixed `profile-image.png`, `profile-image.jpg` or `profile-image.webp`; fixed detected raster media type; inline disposition | Requires the image owner's authenticated session. The caller's upload filename is discarded. Bytes come from PostgreSQL, range processing is disabled and the response receives the common `nosniff` and restrictive CSP policy. |
| Branding logo | Fixed `branding-logo.png`, `branding-logo.jpg` or `branding-logo.webp`; fixed detected raster media type; inline disposition | Public for pre-sign-in branding. The caller's upload filename is discarded. Bytes come from PostgreSQL under the stored detected type and receive `nosniff` and the common browser policy. SVG and arbitrary active types are not accepted. |
| Portable Site export | Server-generated `fylkren-site-{32 lowercase hexadecimal UUID characters}-export.zip`, `application/zip`, attachment disposition | Created from a repeatable-read snapshot, limited to 16 MiB/250 entries and validated before delivery. The filename contains only a server-parsed UUID. The response uses attachment disposition and `nosniff`; the ZIP remains customer data and should be handled according to the receiving organization's classification and malware-scanning policy. |

Print-to-PDF is performed by the user's browser and is not a server file upload or stored server artifact. Backup archives are operator-created recovery artifacts on the server, not HTTP uploads or end-user downloads.

Fylkren has no public upload directory. Uploaded raster bytes live only in PostgreSQL and are returned through fixed API routes; generated exports remain in memory. The API does not serve a filesystem tree. The web container serves only build-time frontend assets from its read-only image, both application containers use read-only root filesystems, and writable temporary mounts are `noexec`.

Client image and package filenames are never used as filesystem paths. Generated export attachment and response names combine fixed prefixes with server-held UUIDs and allowlisted extensions. Portable ZIP entry names are virtual only and are never extracted; traversal, absolute and out-of-prefix paths are rejected before content processing.

## Malicious-content behavior and present limits

Fylkren fully decodes and re-encodes supported raster uploads, rejects disguised or malformed content and never stores a client-controlled filename or executable path. Re-encoding strips metadata, extra frames and trailing content. The resulting raster is newly generated application content rather than the uploaded file. Fylkren does not run an antivirus engine; downstream controls remain relevant for generated export packages and any future general attachment feature.

Portable validation treats the entire ZIP as untrusted structured input. It bounds entry count and total declared uncompressed size before opening content, verifies the package without filesystem extraction and does not make its files downloadable through Fylkren. Validation is not antivirus scanning and is not an import/apply operation. Dataset and attachment descriptors are checked for owner, path, extension, declared media type, length, SHA-256 and structured/decoded content. ASVS 5.4.3 is not applicable to this boundary because no obtained file is served: the only image outputs are re-encoded rasters and the ZIP output is newly generated from application records. Reopen 5.4.3 and require a malware-control design before adding general attachments, package application or any pass-through file response.

If a future feature accepts operational attachments, enables package application, serves package entries, adds a file type, changes a size limit or introduces HTTP/2/3 upload paths, update this inventory and reopen the affected ASVS rows before release.
