Five exploratory attempts preceded the clean run. First, the harness expected the leader's display name in the application shell even though identity is available through the session rather than the shell header. Second, its text-entry helper only supported `input`, not `textarea`. Third, the task-title wait matched the still-open registration dialog instead of waiting for its completed submission. Fourth, the open-card button's decorative icon made raw `textContent` differ from its visible label. Fifth, a substring wait for `Complete` matched other completed-state text before the actual button rendered. Each issue was confined to the new harness, the affected disposable fixture was destroyed, and the next attempt restarted from empty volumes. The final clean run used session identity, element-type-aware input, dialog closure, visible nested button labels and exact actionable-button/status polling.

This is a browser-level subset of E2E-01, not its final release acceptance. It does not yet verify classification, print/PDF headers, audit presentation, overview/workload counters, notification creation and delivery, keyboard/screen-reader behavior, multiple browser engines or a separate actor for report approval. E2E-01 and roadmap gate 3 remain open until those controls and the rest of the maintained matrix have release-candidate evidence.
