## Deviation and rerun

`E2E-10-T01` was a **test expectation error**, not a product defect. An earlier attempt selected the receiver task by `parentWorkItemId == senderTrackingId` from the receiver's API overview and reported zero. Read-only inspection of the synthetic database showed that the task had in fact been created exactly once in the correct receiving site and linked to that tracking item. The receiver's public projection intentionally renders `parentWorkItemId` as `null` across the site boundary. The test was corrected to select by the unique title and instruction and to assert that the internal ID stays hidden. The complete test chain was rerun from a fresh database and passed. No application code was changed for this deviation.

## Not covered and release status

This was an API-level regression, not browser acceptance. It did **not** verify the visual task cards, list counts, `Requires action`, notification recipients or delivery, autosave under a browser refresh, classification, PDF/print, concurrent release requests, or final reports for the newly released E2E-10 branches. Those controls remain in the matrix and need a dated manual or additional automated evidence record before E2E-10 can be marked complete for release.

The isolated Compose project and its named synthetic database/key volumes were removed after the run. No ordinary deployment data or external service was modified.
